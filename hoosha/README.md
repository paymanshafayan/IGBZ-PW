# هوشا

یک دستیار عامل (agent) که **روی دستگاه خودت** اجرا می‌شود، **ابزار واقعی** دارد
(خواندن و نوشتن فایل، اجرای فرمان، جستجو، وب)، **اسکیل و پلاگین** نصب می‌کند، به
**MCP server** وصل می‌شود، و با **هر پرووایدری** کار می‌کند.

نسخهٔ **۰.۴** — هسته، رابط کاربری، حالت بدون‌رابط و SDK.

---

## نصب

نیاز: **Node.js نسخهٔ ۲۰ یا بالاتر** ([nodejs.org](https://nodejs.org)).

```bash
cd hoosha
npm install
npm install -g .
hoosha
```

همین. پنجره (یا مرورگر) روی `http://127.0.0.1:7788` باز می‌شود.

بدون نصب سراسری:

```bash
npm install
node src/cli.js
```

### گزینه‌ها

```
hoosha --dir /path/to/project   پوشهٔ کاری
hoosha --port 7788              پورت
hoosha --host 0.0.0.0           شنیدن روی شبکه (پیش‌فرض فقط لوکال)
hoosha --no-open                پنجره باز نشود
```

### حالت بدون‌رابط (headless)

برای اسکریپت، CI، و هر جایی که پنجره معنا ندارد:

```bash
hoosha -p "تست‌ها را اجرا کن و اگر قرمز شد دلیلش را بگو"
hoosha -p - < task.txt                       # پرامپت از ورودی استاندارد
hoosha -p "بازبینی کن" --output-format json  # خروجی ماشین‌خوان
hoosha -p "…" --output-format stream-json    # هر رویداد، یک خط JSON
hoosha -p "…" --mode auto                    # بدون تأیید
hoosha -p "…" --allow "bash:npm test"        # فقط همین یکی بی‌پرسش
hoosha -p "…" --allowed-tools read_file,grep # دست مدل را ببند
hoosha -p "…" --max-turns 8 --model gpt-4o
```

> در این حالت **هر ابزاری که تأیید بخواهد رد می‌شود**، مگر `--mode auto` بدهی یا با
> `--allow` قاعده بگذاری. یک اسکریپت خودکار نباید بی‌سروصدا اجازهٔ کار خطرناک بگیرد.
> کد خروج: `0` موفق · `1` خطا در اجرا · `2` پرامپت خالی · `3` تنظیمات ناقص.

### استفاده به‌عنوان کتابخانه

```js
import { query, createHoosha } from 'hoosha';

const out = await query( { prompt: 'این پروژه چه می‌کند؟', workspace: '.', mode: 'plan' } );
console.log( out.text, out.usage );

const h = await createHoosha( { workspace: '.', onEvent: ( e ) => console.log( e.type ) } );
h.onPermission( ( req ) => req.name === 'read_file' );      // تصمیم با تو
h.onQuestion( () => 'راه تمیز' );
await h.send( 'یک تست برای src/diff.js بنویس' );
await h.close();
```

### پنجرهٔ مستقل (اختیاری، بدون نصب چیزی)

در Chrome یا Edge روی آیکون **Install** در نوار آدرس بزن — هوشا در یک پنجرهٔ جدا بدون نوار
مرورگر باز می‌شود. برای کار روزمره همین کافی است.

پوستهٔ Electron هم در `desktop/main.js` هست (`npm i -D electron && npm run desktop`)، ولی
مسیر پیش‌فرض همان وب‌اپ است.

| **ریل کناری** | کارهای جاری، شل‌های پس‌زمینه (خواندن خروجی و توقف)، چک‌پوینت‌ها، تغییرات گیت |

## ابزارها

`read_file` · `write_file` · `edit_file` · `multi_edit` · `list_dir` · `glob` · `grep` ·
`bash` (با اجرای پس‌زمینه) · `bash_output` · `kill_shell` · `web_fetch` · `web_search` ·
`todo_write` · `exit_plan_mode` · `ask_user_question` · `skill` · `task` ·
`read_mcp_resource` (وقتی سروری منبع داشته باشد) · و هر ابزاری که از **MCP** بیاید.

**اجرای موازی:** اگر مدل در یک نوبت چند ابزار *خواندنی* بخواهد، با هم اجرا می‌شوند و
نتیجه‌ها به همان ترتیبِ درخواست برمی‌گردند. هر چیزی که می‌نویسد یا اجرا می‌کند ترتیبی
می‌ماند — هم چون ممکن است روی هم اثر بگذارند، هم چون دروازهٔ تأیید نباید چند پنجره را با هم
جلوی کاربر بگذارد.

همه‌شان همیشه در دسترس‌اند. آنچه کنترل می‌شود **اجازه** است، نه توانایی:

| حالت | رفتار |
|---|---|
| **پلن** | فقط بررسی و خواندن. هر ابزاری که چیزی را تغییر بدهد رد می‌شود. |
| **عادی** (پیش‌فرض) | خواندن آزاد؛ نوشتن، ویرایش و اجرای فرمان **تأیید** می‌خواهند. |
| **خودکار** | همه‌چیز بدون پرسش، جز آنچه در فهرست ممنوع گذاشته‌ای. |

قاعده‌ها در `~/.hoosha/config.json` و می‌توانند پیشوندی باشند:

```json
{
  "permissions": {
    "mode": "default",
    "allow": [ "bash:git status", "bash:npm test" ],
    "deny":  [ "bash:rm -rf" ]
  }
}
```

**محدودهٔ کار:** ابزارهای فایل فقط داخل «پوشهٔ کاری» کار می‌کنند؛ مسیر بیرون از آن رد می‌شود.

## اسکیل‌ها

فرمت استاندارد `SKILL.md` — یعنی **اسکیل‌های آماده بدون تغییر نصب می‌شوند**.

```
~/.hoosha/skills/<نام>/SKILL.md              سراسری
<پروژه>/.hoosha/skills/<نام>/SKILL.md         مخصوص همین پروژه (اولویت بالاتر)
```

```markdown
---
name: fa-seo
description: بهینه‌سازی عنوان و متای فارسی
allowed-tools:
  - read_file
  - grep
---
۱. کلیدواژهٔ اصلی در ۶۰ نویسهٔ اول عنوان.
۲. متا دیسکریپشن ۱۴۰ تا ۱۵۵ نویسه.
```

فقط **نام و توضیح** اسکیل در پرامپت سیستمی می‌نشیند؛ متن کامل وقتی خوانده می‌شود که مدل
ابزار `skill` را صدا بزند. برای همین می‌شود ده‌ها اسکیل داشت بدون اینکه کانتکست پر شود.

## کانکتورها (MCP)

از **تنظیمات → کانکتورها** می‌شود کانکتور ساخت، آزمود، خاموش/روشن و حذف کرد — هر دو نوع
`stdio` (اجرای فرمان محلی) و `HTTP`، در محدودهٔ سراسری یا فقط همین پروژه، با ویرایشگر
متغیر محیطی و هدر. دکمهٔ «تست اتصال» واقعاً وصل می‌شود و فهرست ابزارها را برمی‌گرداند.

**پرامپت‌های MCP** خودکار به دستور اسلش تبدیل می‌شوند (`/mcp__<سرور>__<پرامپت>`) و
**منابع MCP** با ابزار `read_mcp_resource` خوانده می‌شوند.

فایل‌های زیر هم مثل قبل کار می‌کنند (اگر ترجیح می‌دهی دستی بنویسی):

```json
{
  "mcpServers": {
    "files":  { "command": "npx", "args": [ "-y", "@modelcontextprotocol/server-filesystem", "." ] },
    "remote": { "url": "https://example.com/mcp", "headers": { "Authorization": "Bearer …" } }
  }
}
```

در `~/.hoosha/config.json` (سراسری) یا `<پروژه>/.hoosha/mcp.json` (پروژه‌ای).
ابزارهای هر سرور با نام `mcp__<سرور>__<ابزار>` می‌آیند تا در قواعد مجوز جدا نشانه‌پذیر باشند.
یک سرور خراب، بالا آمدن برنامه را نمی‌خواباند؛ وضعیتش در پنل **افزونه‌ها** دیده می‌شود.

## پلاگین‌ها

یک پلاگین فقط یک پوشه است:

```
plugin.json          { "name": "…", "version": "…" }
skills/<x>/SKILL.md
commands/<x>.md
.mcp.json            سرورهای MCP این پلاگین
hooks.json           هوک‌های این پلاگین
```

نصب از مخزن گیت یا مسیر محلی:

```
/plugin install owner/repo
/plugin install ./my-plugin
/plugin list
/plugin remove my-plugin
```

**نصب هیچ کدی اجرا نمی‌کند** — فقط فایل کپی می‌شود. کد وقتی اجرا می‌شود که عامل ابزاری را
صدا بزند و از دروازهٔ مجوز رد شود.

مارکت‌پلیس هم یک مخزن گیت است با فایل `marketplace.json`:

```json
{ "name": "…", "plugins": [ { "name": "seo", "source": "owner/repo", "description": "…" } ] }
```

## دستورهای اسلش

داخلی: `/help` `/clear` `/compact` `/mode` `/model` `/config` `/provider` `/connectors`
`/mcp` `/tools` `/skills` `/agents` `/plugin` `/hooks` `/memory` `/init` `/permissions`
`/usage` `/cost` `/rewind` `/bashes` `/todos` `/export` `/doctor` `/status` `/workspace`
`/sessions` `/resume`

دستور خودت: هر فایل مارک‌داون در `~/.hoosha/commands/` یا `<پروژه>/.hoosha/commands/`

```markdown
---
description: بازبینی یک فایل با تمرکز مشخص
---
فایل $1 را بخوان و با تمرکز روی «$2» بازبینی کن.
```

`$ARGUMENTS` کل ورودی است و `$1`،`$2`… پارامترهای جدا. در کادر ورودی با `/` فهرست
دستورها با تکمیل خودکار باز می‌شود.

## هوک‌ها

هر هوک یک فرمان پوسته است که JSON روی stdin می‌گیرد.

```json
{
  "hooks": {
    "PreToolUse":      [ { "matcher": "bash", "command": "./scripts/audit.sh" } ],
    "UserPromptSubmit":[ { "command": "echo '{\"additionalContext\":\"شاخه: main\"}'" } ]
  }
}
```

رویدادها: `SessionStart` · `UserPromptSubmit` · `PreToolUse` · `PostToolUse` · `Stop` ·
`SessionEnd`.
**توقف:** خروج با کد ۲ یا چاپ `{"decision":"block","reason":"…"}`.
**کانتکست اضافه:** چاپ `{"additionalContext":"…"}` یا هر متن خام.

هوک `PreToolUse` حتی جلوی ابزارِ *مجاز* را هم می‌گیرد — این نقطه، جای سیاست سازمانی است.

## زیرعامل، چک‌پوینت و کانتکست

- **`task`**: یک نشست تازه با بودجهٔ خودش که فقط **خلاصهٔ نتیجه** را برمی‌گرداند. برای
  کاوش‌های طولانی که کانتکست اصلی را خراب می‌کنند. زیرعامل خودش `task` ندارد (جلوی بازگشت
  بی‌پایان).
- **زیرعامل تعریف‌شده**: هر فایل `~/.hoosha/agents/<نام>.md` (یا `<پروژه>/.hoosha/agents/`)
  یک متخصص با پرامپت، مدل و ابزارهای خودش است؛ مدل با `subagent_type` صدایش می‌زند.
  ساختنش از **تنظیمات → زیرعامل‌ها**.
- **چک‌پوینت و بازگشت**: قبل از هر پیام تو یک چک‌پوینت باز می‌شود و قبل از هر تغییرِ فایل،
  نسخهٔ فعلی‌اش پشتیبان گرفته می‌شود. با `Esc Esc` یا `/rewind` می‌شود فایل‌ها را به همان
  لحظه برگرداند و گفتگو را هم تا همان‌جا برید.
- **فشرده‌سازی**: گفتگوی بلند خودکار (یا با `/compact`) به یک خلاصه تبدیل می‌شود. اگر
  خلاصه‌سازی شکست بخورد، گفتگو دست‌نخورده می‌ماند.
- **`HOOSHA.md`** در ریشهٔ پروژه، همیشه در پرامپت سیستمی می‌نشیند — همان نقش دستورالعمل
  پروژه.

## تنظیمات و داده

مسیر پیش‌فرض `~/.hoosha` است و با متغیر `HOOSHA_HOME` قابل تغییر:

```bash
HOOSHA_HOME=/path/to/config hoosha
```

```
~/.hoosha/config.json     پروفایل‌ها، کلیدها، قواعد مجوز، MCP، هوک‌ها
~/.hoosha/skills/         اسکیل‌ها
~/.hoosha/commands/       دستورهای خودت
~/.hoosha/plugins/        پلاگین‌ها
~/.hoosha/agents/         زیرعامل‌های تعریف‌شده
~/.hoosha/sessions/       تاریخچهٔ گفتگوها
~/.hoosha/checkpoints/    پشتیبان فایل‌ها برای بازگشت
~/.hoosha/usage.json      دفتر مصرف روزانه
```

> **کلید API در همین فایل ذخیره می‌شود** (دسترسی فایل روی `600` بسته می‌شود). اگر روی
> دستگاه مشترک کار می‌کنی، این را بدان.

## تست

```bash
node test/run.mjs     # ۷۶ تست واحد
node test/live.mjs    # ۲۳ آزمون زنده روی یک سرور واقعی
```

**۷۶ تست واحد، بدون وابستگی.** ابزارها، مجوزها، اسکیل، دستور، هوک، فشرده‌سازی، هر دو
پروتکل پرووایدر (با سرور جعلی)، زیرعامل، MCP (با یک سرور MCP واقعی)، پلاگین، حلقهٔ عامل،
دیف، چک‌پوینت، کانکتور، عامل‌ها، شل پس‌زمینه، جستجوی فازی، هزینه، خروجی گفتگو،
محتوای چندرسانه‌ای، تصویر و استدلال در هر دو پروتکل، اجرای موازی، SDK، و پرامپت/منبع MCP.

**۲۳ آزمون زنده.** سرور واقعی بالا می‌آید، SSE وصل می‌شود، و همان مسیرهایی صدا زده می‌شوند
که رابط کاربری صدا می‌زند: دروازهٔ تأیید، دیف، بازگشت، کارت نقشه، کارت پرسش، شل پس‌زمینه،
افزودن و حذف کانکتور MCP، پرامپت MCP، پیوست تصویر، ساخت زیرعامل و دستور، خروجی گفتگو، و
اجرای واقعی `hoosha -p` در یک پروسهٔ جدا.

قاعده‌ای که از مخزن اصلی می‌آید: **سوئیتی که بار اول سبز شود چیزی ثابت نکرده.** هر تست
اینجا با خراب‌کردن عمدی کد قرمز شده است.

## وضعیت

**هست و تست شده:** حلقهٔ عامل · ۱۵ ابزار داخلی + `skill` + `task` + ابزارهای MCP ·
سه حالت مجوز و قواعد پیشوندی · دروازهٔ تأیید · محدودهٔ پوشهٔ کاری · پروتکل OpenAI و
Anthropic · واکشی فهرست مدل · اسکیل (SKILL.md) · پلاگین و مارکت‌پلیس · MCP (stdio و HTTP) ·
هوک با قابلیت توقف · دستورهای اسلش داخلی و سفارشی با تکمیل خودکار · زیرعامل ·
فشرده‌سازی کانتکست · `HOOSHA.md` · نشست‌ها · شمارش توکن · رابط فارسی با استریم.

به‌علاوه: چک‌پوینت و بازگشت · شل پس‌زمینه · جستجوی وب · حالت نقشه با کارت تأیید ·
پرسش چندگزینه‌ای از کاربر · زیرعامل تعریف‌شده · هزینه و دفتر مصرف · خروجی گفتگو ·
تشخیص خرابی · و رابط کاملی که همهٔ این‌ها را قابل‌کلیک می‌کند
(جدول مقایسه با Claude Code در `DESIGN-UI-PARITY.md`).

به‌علاوه در ۰.۴: **حالت بدون‌رابط** · **SDK** · **ورودی تصویر** · **بلوک فکر مدل‌های
استدلالی** · **اجرای موازی ابزارهای خواندنی** · **پرامپت و منبع MCP** · انتخاب سریع مدل.

**هنوز نیست:** elicitation در MCP · اجرای سندباکس‌شدهٔ ابزارها · ترمینال داخل برنامه ·
`NotebookEdit`.
